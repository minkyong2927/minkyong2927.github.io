ESTimate — HR Performance Review Platform

ESTsoft · Sole developer (requirements, build, deploy, operate) · Jul 2026 – present

ESTimate runs peer reviews, leadership reviews, self-assessments, and final grading for the company. There was no product spec: I turned two HR policy manuals into a functional specification, built the system, and launched it company-wide in three months. It replaced a per-seat commercial SaaS.

What I built

  • Full review lifecycle: reviewer nomination → leader approval → writing → grading, plus export to the HR team's existing Excel formats.
  • Roster ingestion from Excel that maps org chart, dual roles, and affiliates, and decides who is eligible for review.
  • Admin console with change history, data checks, and an audit log of every admin action.

Enterprise integration & security

  • Single sign-on with Microsoft Entra ID and Google Workspace (OAuth 2.0 / OIDC), with a switch to enforce SSO-only at launch.
  • TOTP two-factor authentication for administrators, Content Security Policy, and role-based access for employees, leaders, and HR admins.
  • Handled a reported exposure of roster data in the public JavaScript bundle: removed it from the client build and added a rule that no real data lives in front-end source.

Reliability & operations

  • Load-tested with k6 and found that saving whole arrays crashed PostgreSQL with out-of-memory errors; redesigned storage to row-level records. 300 concurrent submissions now complete in 0.73 s.
  • Automated a 10-stage end-to-end scenario with Playwright; caught 27 issues before launch.
  • Collected front-end and server errors automatically and shipped same-day fixes for user reports, including a browser storage quota overflow and a request-size limit that had silently dropped approved tasks (all records restored).
  • Wrote consistency-check scripts that compare nominations against writing tasks after every deploy.

SQL Agent — Ask Business Data in Plain Language

Personal project · Oct 2026 · github.com/minkyong2927/sql-agent

An operations team asks a question in plain language ("How many gift payouts are overdue, and for how much?"). A Claude agent writes DuckDB SQL through a tool, runs it, and answers only from the result. The data is a synthetic model of a telecom and rental sign-up broker: 11 tables covering customers, consultations, applications, installations, gift payouts, and cancellations.

Guardrails in layers

  • Every query is parsed with sqlglot before it runs: one statement, read queries only, no DELETE / DROP / COPY / ATTACH / SET, and an allow-list of tables that also blocks file-reading functions such as read_csv('…/.env').
  • The database opens read-only with external access disabled, so a missed check still cannot write or read local files.
  • Row limits, a cap on SQL calls per question, and SQL errors returned to the model so it can fix its own query.

Evaluation-driven iteration

A 40-question set (easy → trap questions such as double counting after a join, people vs. rows, and questions the data cannot answer) graded two ways: does the answer contain the right values, and did those values come from an executed query?

Baseline27/30
+ "compute in SQL" rule30/30

Answers backed by executed SQL (Claude Opus). The 3 misses were ratios the model calculated itself; one prompt rule fixed them.

  • Claude Haiku matched Opus on all 40 questions at about 1/40 of the cost ($0.02 vs $0.80 per 30-question run).
  • Reading failures instead of trusting the score found two bugs of my own: an unhandled tokenizer error in the SQL guard, and an off-by-one date boundary in one reference answer.

Delivery

  • FastAPI service (POST /ask, health check, demo page) with input validation and model allow-list.
  • GitHub Actions runs the guard, API, and grader tests on every push with the LLM mocked, so CI costs nothing.

FGAI — Facial Emotion Recognition for Focus Groups Grand Prize

ESTsoft AI Developer Program (K-Digital Training) · Final team project · Jan 2026

In a focus group interview, one moderator watches several people at once, can miss reactions, and judges them subjectively. I proposed reading each participant's facial expressions with AI to surface their real reactions, and named and scoped the project.

Modeling

Faces in focus groups are mostly subtle or neutral, so a single model struggled to separate four classes (anger, happy, panic, sadness). We compared about 15 image classifiers and combined the top models with complementary strengths.

Soft voting (10)89.11%
Weighted voting89.40%
Top-5 ensemble89.83%
Top-3 ensemble90.54%

Final: ConvNeXt + EfficientNetV2 + MaxViT · F1 0.9053 · ROC AUC 0.9805 · +1.28 pp over the best single model

Real-time dashboard (built solo)

Webcam frame → compress and base64-encode → server → MediaPipe face detection → crop to 224 px → ensemble inference (averaged logits) → probabilities, face box, and session stats (count, average, latency) rendered in Streamlit.

UVA Radiation Forecasting Grand Prize

ESTsoft AI Developer Program (K-Digital Training) · Team project · 2025

Forecasts next-day UVA levels from weather, solar, atmospheric, and radiation data, for use cases like UV alerts and outdoor-activity guidance.

  • Collected and merged public weather and air-quality data; filled gaps with time-based interpolation.
  • EDA showed strong seasonality (peak in June–July) and high correlation with solar radiation, which guided feature design.
  • Moved from univariate models (Prophet, ARIMA, LSTM) to multivariate (Random Forest, XGBoost, LSTM), then stacked XGBoost + LSTM.
  • Result: out-of-fold R² 0.7541, MAE 0.1427, RMSE 0.1977.
